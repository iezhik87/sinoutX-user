# SinoutX — QA Checklist (функциональный каталог)

Полный каталог проверок «как человек»: для каждой функции — шаги и **ожидаемый результат**.
Годится для ручного прохода, для браузер-агента и как ТЗ для Playwright-спеков (`packages/e2e`).
ID кейсов (`AUTH-01` и т.п.) предназначены для маппинга 1:1 на будущие спеки.

Легенда: ✅ ожидаемый результат · ⚠️ известный нюанс · 🔒 проверка доступа.

---

## 0. Предусловия / окружение

- ENV: `BASE_URL` (прод — https://app.sinout.dasp.top, локал — http://localhost:8090).
- Перед прогоном **очистить Service Worker и кэш** (Application → Service Workers → Unregister, Clear site data) — иначе тест может идти по старому бандлу.
- Должны быть подняты: backend(3010), frontend(nginx), postgres, redis, meilisearch, minio. Email (Zoho SMTP) настроен в админке.
- Тестовые аккаунты: OWNER (полный доступ), VIEWER (read-only) — для проверок ролей.

### Как это превратить в Playwright-спеки
- Каждый ID → один `test('ID — описание', ...)`; группировать по разделам в файлы (`auth.spec.ts`, `pages.spec.ts`, …).
- Авторизация — через существующий `auth.setup.ts` (storageState, JWT в localStorage; cookies не используются).
- `getFirstProjectId()` берёт projectId из `fixtures.json` (см. `helpers.ts`).
- Для AI-кейсов — пометить `test.skip` при отсутствии AI-ключа (как уже сделано для `13-ai-features`).
