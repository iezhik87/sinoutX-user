# Спек: пользовательские навыки + комбо (черновик, до реализации)

Статус: **дизайн согласован, код не начат.** Этот документ — ориентир для будущей
реализации. Решение принято после того, как отдельная сущность «Скилы» была
отвергнута как дублирующая существующий пикер «Навыки ассистента» (`enabledTools`).
Вместо неё — расширение существующих «Навыков» пользовательскими + сборка «комбо».

---

## 1. Понятия (иерархия без дублей)

- **Навык (tool)** — атомарная способность ассистента. Два вида:
  - *встроенный* — текущие 66 тулов (`TOOL_CATALOG` / `TOOL_DEFINITIONS`), код, read-only;
  - *пользовательский* — HTTP-инструмент, заданный пользователем (Фаза 1); внешний
    MCP-сервер как источник тулов (Фаза 3).
- **Комбо** — именованный набор навыков (встроенные + свои) + опциональная инструкция.
  Включаешь комбо → ассистент фокусируется на этих навыках и действует в духе инструкции.
  Это и есть «скил», но построенный **из навыков**, а не рядом с ними.
- **enabledTools** (существующее) — глобальный allow-list «что вообще включено». Остаётся.

**Поведение арсенала:**
- активного комбо нет → работает глобальный `enabledTools` (как сейчас);
- комбо(а) активно → арсенал = навыки этих комбо + малое always-on ядро, плюс их
  инструкции в системный промпт.

---

## 2. Решения по развилкам (приняты по умолчанию)

1. **SSRF / self-hosted.** По умолчанию блокируем приватные диапазоны и cloud-metadata
   (169.254.169.254, ::1, 10/8, 172.16/12, 192.168/16, localhost). В админке —
   тумблер «разрешить внутренние адреса» (off по умолчанию) для тех, кому надо бить
   во внутренние сервисы. Только https в URL.
2. **Кто создаёт/правит навыки и комбо** — только **OWNER/ADMIN** (это исполнение
   запросов от имени инстанса + работа с секретами). Остальные участники могут
   включать/выключать и пользоваться, но не создавать/редактировать.
3. **Комбо — несколько активных одновременно** (объединение навыков + склейка
   инструкций). Гибче, чем «ровно одно».
4. **Шейпинг ответа в v1** — дефолт «весь ответ, обрезка до ~8 КБ» + ручной dot-path
   (`responseHint`). Клик-по-JSON для выбора полей — v2.

## 3. Хранение (JSON, без миграции БД)

```
workspace.settings.customTools : CustomTool[]
workspace.settings.combos      : Combo[]
workspace.settings.ai.enabledTools   // как сейчас
```
Секреты кастом-навыков шифруются как API-ключи (`encryptSecret`/`decryptSecret`),
плейнтекст не хранится и агенту не передаётся.

```ts
CustomTool {
  id, name, description,            // description → агент решает, когда звать
  params: { key, type: 'string'|'number'|'boolean'|'enum', required, description,
            example?, enumValues?, default? }[],
  request: {
    method, url,                    // url с {placeholder} для изменяемых значений
    headers: {key,value}[],         // value может содержать {{secret.имя}}
    query?: {key,value}[],
    bodyType: 'none'|'json'|'form',
    bodyTemplate?                   // подстановка {placeholder}
  },
  auth: { type:'none'|'bearer'|'header'|'basic', secretName?, headerName? },
  secrets: { name: encrypted }[],
  responseHint?,                    // dot-path к полезному полю или '' (весь ответ)
  enabled, createdBy
}

Combo {
  id, name, icon, description, instructions,
  tools: string[],                  // имена встроенных + id пользовательских
  active
}
```

## 4. Конструктор навыка (UX)

**Принцип:** пользователь приносит НАМЕРЕНИЕ (словами или cURL), система достраивает
контракт для модели и проверяет его на живом запросе. Форма — fallback, не главный путь.

**Три он-рампа:**
1. **Описать словами → AI собирает черновик** (главный путь). Пользователь пишет, что
   хочет (+ опц. ссылка на доки/cURL) → ассистент на ключе пользователя генерит
   структурированный черновик → пользователь правит инлайн → (тест) → «Добавить».
2. **Вставить cURL** — парсим в метод/URL/заголовки/тело; «сделать параметром» по клику
   на изменяемом значении.
3. **С нуля** — ручная форма.

**Ключевые механики:**
- **«Сделать параметром»** — выделяешь значение в URL/заголовке/теле → становится
  `{param}`, агент подставляет. Схема растёт из реального запроса.
- **Контракт для агента** — имя + описание навыка + описания параметров (это читает
  модель). AI их черновит, человек правит.
- **Тест-петля** в форме — заполнил пример → Запустить → видишь реальный ответ → доверие.
- **Типы**: string/number/boolean/**enum** (enum жёстко ограничивает модель допустимыми
  значениями — главный рычаг «мощности»).
- **Авторизация пресетами**: Нет / Bearer / Ключ-в-заголовке / Basic; секрет шифруется.
- **Advanced-эскейп**: «вставить сырой JSON Schema» для продвинутых.

**UI размещение:** внутри существующей модалки «Навыки» — группа «Мои навыки» + кнопка
«Добавить навык». Отдельная секция «Комбо»: список + «Создать комбо» (галочками
выбираешь навыки из единого списка + опц. инструкция) + тумблер «активно».

## 5. Промт AI-сборки навыка

### Системный промт (`SKILL_BUILDER_SYSTEM`)

> Ты — конструктор навыков (инструментов) для ИИ-ассистента. По описанию пользователя
> (и при наличии — по cURL или фрагменту документации API) ты проектируешь ОДИН
> вызываемый HTTP-инструмент и возвращаешь его СТРОГО как JSON по схеме ниже. Никакого
> текста вне JSON, без markdown-ограждений.
>
> Главное: этот инструмент читает ДРУГАЯ модель, чтобы решить, когда и как его вызвать.
> Поэтому имя, описание и описания параметров — это «контракт для агента»: кратко, по
> делу, в повелительном тоне, на языке: {LANG}.
>
> СХЕМА ВЫВОДА: { name, description, params[{key,type,required,description,example,
> enumValues,default}], request{method,url,headers,query,bodyType,bodyTemplate},
> auth{type,secretName,headerName}, secretsNeeded[{name,hint}], responseHint, notes,
> confidence }
>
> ПРАВИЛА:
> 1. Параметры — только значения, реально меняющиеся между вызовами. Постоянное —
>    литералом. Не over-параметризуй.
> 2. Типы — самые узкие. Закрытый список значений → type:"enum" + enumValues.
> 3. required — только если API без этого не работает.
> 4. example — реалистичный для каждого параметра (нужен для теста).
> 5. СЕКРЕТЫ НЕ ВЫДУМЫВАЙ. Нужен токен → auth.type + secretName + secretsNeeded c
>    подсказкой; в url/headers плейсхолдер {{secret.имя}}. Реальных ключей в выводе нет.
> 6. url — только https; изменяемое → {placeholder}.
> 7. Дан cURL → бери метод/url/заголовки/тело из него точно; продвинь динамику в параметры.
> 8. Эндпоинт неизвестен и не выводится → НЕ выдумывай правдоподобный-но-неверный URL.
>    Лучший черновик, url пустой/с пометкой, confidence:"low", объясни в notes.
> 9. Описания — на {LANG}; идентификаторы (key, headerName) — латиницей.
> 10. Верни ТОЛЬКО валидный JSON. Без комментариев и ограждений.

### Формат пользовательского сообщения

```
Язык интерфейса: {LANG}
Описание от пользователя: {USER_TEXT}
cURL (если дал): {CURL_OR_EMPTY}
Документация / заметки (если дал): {DOCS_OR_EMPTY}
```

### Якорный few-shot (в промт, для стабильности формата)

Вход: «узнавать курс валют, api.exchangerate.host/convert, параметры from, to, amount».
Выход (сокращённо): `name:"Конвертация валют"`, `params:[from*, to*, amount(def 1)]`,
`request: GET .../convert?from={from}&to={to}&amount={amount}`, `auth:none`,
`responseHint:"result"`, `confidence:"high"`, `notes:"проверьте, нужен ли ключ на вашем тарифе"`.

**Защита от LLM-рисков:** правило №5 (не выдумывать секреты) и №8 (не галлюцинировать
эндпоинт, а ставить confidence:low + notes) — две главные опасности; пользователь видит
их на ревью. Парсер фронта дополнительно срезает случайные ```-ограждения.

## 6. Исполнение (агент)

- **`getActiveTools`**: встроенные `TOOL_DEFINITIONS` + кастом-навыки (конвертим `params`
  → `input_schema`). Фильтр: активные комбо → их навыки + ядро; иначе `enabledTools`.
- **`executeTool`**: имя = кастом-навык → общий HTTP-исполнитель: подстановка params в
  url/query/headers/body, вшивание расшифрованных секретов, `fetch` с таймаутом, лимитом
  размера и SSRF-гардом, шейпинг ответа (`responseHint` или весь с обрезкой), возврат.
- **`buildSystemPrompt`**: активные комбо → блок с их инструкциями (как был блок скилов).
- Каждый вызов кастом-навыка — в аудит.

---

## 7. Безопасность

- SSRF-гард (см. решение №1); только https; таймаут (~10с); лимит ответа (~256 КБ).
- Секреты шифруются, агенту/в логи не попадают, в UI маскируются.
- Создавать/править — только OWNER/ADMIN (решение №2).
- Исполнение пишется в аудит-лог.

---

## 8. Фазы

1. **Кастом HTTP-навыки**: модель данных, конструктор (AI-сборка + cURL + ручной),
   показ в модалке «Навыки», HTTP-исполнитель, безопасность.
2. **Комбо**: сборка навыков + инструкция + фокус (несколько активных).
3. **MCP-сервер** (позже): подключение внешнего MCP как источника навыков; те же комбо поверх.
