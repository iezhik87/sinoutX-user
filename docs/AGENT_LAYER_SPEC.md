# Спек: Агентный слой SinoutX (память + взаимодействие)

Цель: любой внешний агент (Гермес, OpenClaw, …) подключается к SinoutX по MCP и
свободно использует его как **основную память** и **площадку взаимодействия** —
со своим пространством, организованной памятью, доступом к другим модулям и к
встроенному агенту. Всё — в существующей канве (Collections-движок, граф,
воркспейсы+роли, MCP).

Статус: **дизайн согласован, Фаза 1 в разработке.**

---

## 1. Принципы

- **Namespace = воркспейс на агента.** У каждого агента свой приватный
  воркспейс-память (Мерк уже так и сделал — создал свой). Плюс членство в
  **общих** воркспейсах для коллаборации (модель membership + роли уже есть).
- **Память = модуль** на движке Collections (как Медкарта/Финансы), с типизированными
  реестрами и встроенной организацией. Не свалка заметок.
- **Сквозная, не силос.** Память связана со всем воркспейсом и другими модулями
  через граф (`create_link`) и generic-чтение реестров (`list_collections`).
  Будущие модули подхватываются даром (движок декларативный).
- **Инструкция при подключении.** Агент получает правила поведения в момент
  `initialize` (MCP server `instructions`) — действует по ним сразу, без ручной
  вставки оператором.
- **Взаимодействие агентов.** Встроенный агент SinoutX (66 тулов) и внешние —
  равноправные акторы; общаются через общее состояние + делегирование.

---

## 2. Модуль «Память» (Collections)

`moduleId: memory`. Реестры:

- **core (Ядро)** — компактный always-load контекст. Поля: `key` (text), `content`
  (longtext), `pinned` (select yes/no). Кто агент, устойчивые предпочтения,
  указатели на ключевые узлы. Держать коротким.
- **facts (Факты)** — атомарные знания. Поля: `text` (longtext, req), `topic`
  (text), `importance` (select low|medium|high), `source` (text), `date` (datetime).
- **entities (Сущности)** — структурированное знание о вещах. Поля: `name` (text, req),
  `type` (select person|project|concept|place|org|other), `attributes` (longtext),
  `notes` (longtext).
- **episodes (Эпизоды)** — эпизодическая память/лог. Поля: `when` (datetime), `event`
  (longtext, req), `refs` (longtext — на что ссылается).

`ai.systemHints` — для встроенного агента (как вести память). Для внешних —
доставляется через MCP (ниже).

---

## 3. Кросс-модульность (готовые примитивы)

- **Граф/связи:** запись памяти ссылается на любую сущность (страница, задача,
  операция Финансов, запись Бюджета, замер Медкарты) через `create_link`.
- **Generic реестры:** `list_collections({workspaceId})` показывает все модули
  воркспейса; `query_records` читает их. Новый модуль виден автоматически.
- **Поиск:** `search` по всему воркспейсу (полнотекст); семантика — Фаза 2.

---

## 4. Инструкция при подключении

Два уровня:
1. **MCP server `instructions`** (авто, при `initialize`) — компактный протокол:
   - на входе: `setup_memory` (свой воркспейс + модуль) или `list_workspaces`;
     загрузи Ядро;
   - карта памяти (core/facts/entities/episodes), ключи полей — из `list_collections`;
   - кросс-модульность: смотри другие модули, линкуй факты к их записям;
   - ты не один: делегируй встроенному агенту `ask_assistant`, есть общие воркспейсы;
   - дисциплина: Ядро компактно, важное сохраняй сразу, перед ответом — recall.
2. **`memory_guide`** (MCP prompt/resource, по запросу) — полная версия с примерами.

---

## 5. Взаимодействие агентов

- **Неявное (общее состояние):** общий воркспейс, где встроенный и внешние агенты
  работают по одним данным; роли governance'ят доступ.
- **Явное:**
  - внешний → встроенный: `ask_assistant` (обёртка `askAI` → `/ai/chat`);
  - встроенный → внешний: **кастом-HTTP-навыки** (Фаза 1 кастом-навыков уже есть) —
    встроенный агент дёргает вебхук внешнего;
  - **directory:** реестр «Агенты» в общем воркспейсе (кто, что умеет, endpoint);
  - **хэндофф:** задача/заметка для агента или реестр «Сообщения» + уведомления.

## 6. Фазы

**Фаза 1 (сейчас):**
- модуль «Память» (manifest + регистрация);
- MCP server `instructions` (on-connect);
- `ask_assistant` (делегирование встроенному);
- `setup_memory` (воркспейс агента + установка модуля одним вызовом);
- (реестр-тулы `list_collections`/`query_records`/`create_record`/… уже выведены).

**Фаза 2:** семантический recall (эмбеддинги: pgvector или BYOK), `remember`/`recall`
сахар, knowledge-тулы в MCP (`search_workspace`, `find_related_pages`,
`read_page_with_children`), `memory_guide` prompt/resource.

**Фаза 3:** directory «Агенты» + хэндофф/сообщения + уведомления; общие воркспейсы
как «командная» площадка; авто-контекст Ядра как MCP resource.
